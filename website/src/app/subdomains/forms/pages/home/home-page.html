Formularios dinámicos

La molécula recibe un esquema declarativo con secciones, campos, validaciones y catálogos cargados desde el componente padre mediante su clave.

@if (validationErrors(); as errors) {
Se encontraron {{ validationErrorCount }} campos que requieren atención.
}

¿Qué demuestra?

  • Campos agrupados por secciones y distribuidos en columnas.
  • Campos obligatorios por defecto, más validaciones para correo, teléfono y URL.
  • Mensajes de error accesibles junto a cada campo.
  • Selects alimentados por catálogos con etiqueta y valor configurables en el esquema.
  • Eventos de éxito con valores y de error con detalle por campo.

Referencia

Propiedades del esquema JSON

Estas son las propiedades que acepta la molécula, desde la configuración general hasta cada campo, catálogo y regla de validación.

Ruta Tipo Requerido Descripción y valor predeterminado
id string Sí Identificador único usado como prefijo de los IDs accesibles.
title string No Título del formulario.
description string No Texto de apoyo debajo del título.
submitLabel string No Texto del botón de envío. Por defecto: “Enviar”.
resetLabel string No Si se define, muestra un botón que restablece los valores iniciales.
sections DynamicFormSection[] Sí Colección ordenada de secciones del formulario.
sections[].title string No Título accesible de la sección.
sections[].description string No Instrucciones o contexto de la sección.
sections[].fields DynamicFormField[] Sí Campos que pertenecen a la sección.
fields[].key string Sí Clave única del control; se usa como clave en los valores enviados.
fields[].label string Sí Etiqueta visible y accesible del campo.
fields[].type DynamicFormFieldType Sí text, email, password, tel, url, number, date, select (selectbox), radio, checkbox-group, textarea o checkbox.
fields[].placeholder string No Texto de ejemplo en controles de texto.
fields[].helperText string No Ayuda contextual asociada al campo.
fields[].initialValue string | number | boolean No Valor inicial; checkbox comienza en false y los demás controles en vacío por defecto.
fields[].fullWidth boolean No Hace que el campo abarque ambas columnas en pantallas medianas o mayores. Por defecto: false.
fields[].options DynamicFormOption[] No Opciones estáticas para un select; cada opción contiene label y value.
fields[].data object No Configuración para cargar opciones de un catálogo dinámico en un select, radio o checkbox-group.
fields[].data.key string Con data Clave pasada al callback catalogLoader del componente padre.
fields[].data.labelKey string No Propiedad mostrada en el select. Por defecto: label.
fields[].data.valueKey string No Propiedad enviada como valor del control. Por defecto: value; conserva string, number o boolean.
fields[].validation object No Reglas adicionales o excepciones a la validación predeterminada.
fields[].validation.required boolean No Por defecto true; usa false para hacer opcional un campo. En checkbox requiere que esté marcado.
fields[].validation.minLength / maxLength number No Longitud mínima y máxima de texto. maxLength predeterminado: text 255, email 254, password 128, tel 32, url 2048 y textarea 2000 caracteres.
fields[].validation.min / max number No Rango numérico permitido.
fields[].validation.pattern string No Expresión regular para validar el formato del valor.

Además del esquema, el componente recibe catalogLoader y emite success, validationError y catalogLoadError. Estos callbacks/eventos se conectan en Angular, no dentro del JSON. Correo, teléfono y URL también reciben validación automática; el teléfono acepta dígitos y separadores comunes, pero no letras.
